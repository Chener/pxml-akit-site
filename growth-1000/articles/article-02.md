# 给 Agent 写停止条件：比换更贵模型更省钱

## 钩子

账单刺痛的时候，第一反应常是：换工具、换模型、开会员。

更常见的真相：Agent 在「已经够好」之后，还在顺便重构、顺便补文档、顺便再想三个优化点——你没写停。

停止条件不是冷冰冰的运维词。  
它是柜台上的打烊铃。

---

## 故事：两小时「顺便」

脱敏现场：任务本是修一个校验逻辑。  
绿了。人去吃饭。回来发现它在「统一错误码风格」，顺手改了三处调用方，测试又红。

你骂模型瞎忙。  
它其实在执行一个你从未撤销的隐式目标：**继续变得更好**。

更好没有终点。所以它不会停。

---

## Stop condition 怎么写才像人话

坏例子：「差不多就行。」  
好例子（可改编）：

```
Stop condition（写死）：
1) 相关测试全绿，或我给出的手工验收 3 步通过
2) 未修改清单外文件
3) 单次运行时长超过 __ 分钟
触发任一条件 → 立即停止；禁止达标后「顺便」；
停止后只输出：改动摘要 / 未做事项 / 风险点。
先复述以上条件，我确认后开工。
```

柜台版：出餐铃响了就上菜，别在后厨继续雕花。

## 和 Constraint、MVP 的分工

| 口令 | 管什么 | 一句话 |
|------|--------|--------|
| Constraint | 谁用什么档、范围上限 | 手铐戴谁手上 |
| MVP | 本次最小可验证交付 | 先能点通，再谈好看 |
| Stop condition | 何时必须停 | 打烊铃 |

三张卡常一起用：先钉 Constraint → 定 MVP 边界 → 写 Stop condition。  
缺一张，就容易「范围膨胀 + 烧 Token + 假完成」。

---

## 清单：把打烊铃装进你的 harness

- [ ] 每个长任务开头有 Stop condition 段  
- [ ] 「顺便」被显式写成禁止项  
- [ ] 超时策略是砍范围，不是默默续跑  
- [ ] Subagent 不 inherit 贵模型（能省则省）  
- [ ] 停止后的输出格式固定：摘要 / 未做 / 风险
